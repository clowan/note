**你已经赢了，因为细节你全都知道。**

## 1. 技术栈选择

**唯一重要的原则：选你最熟的，不要为了学新东西而换栈。**

| 层 | 推荐选择 | 理由 |
|---|---|---|
| 后端语言 | TypeScript / Node.js | 和 Clowder 一致，遇到设计问题可以直接对照原代码 |
| 框架 | Fastify 或 Express | 轻，够用，不学新东西 |
| 实时通信 | WebSocket（`ws` 包） | 流式输出必须的，不要用 SSE（不能双向） |
| 存储 | SQLite（`better-sqlite3`） | 里程碑 1-4 不需要 Redis，零部署成本 |
| 前端 | 任意，或者纯 curl/wscat | 前端不是重点，先用命令行 client 打通 |
| Agent CLI | Claude Code（`claude`）或任意装了的 | 本地已有什么就用什么 |

**绝对不要同时选多个新技术。** 如果后端不熟，就选熟的后端；如果 TypeScript 不熟，用 JavaScript 也一样能做完。

## 3. 里程碑路线

### M1 · 调起一个 Agent 并看到流式输出（2~3 天）

**做完能演示**：浏览器（或 wscat）发消息 → 后端 spawn claude → 流式文字实时出现。

**关键代码框架**：

```typescript
// src/agent/spawn.ts
import { spawn } from 'child_process';

export interface SpawnOptions {
  prompt: string;
  sessionId?: string;  // 里程碑 4 才用
  systemPrompt?: string;
}

export async function* invokeAgent(opts: SpawnOptions): AsyncGenerator<string> {
  const args = ['--output-format', 'stream-json', '--print', opts.prompt];
  if (opts.sessionId) args.push('--resume', opts.sessionId);

  const child = spawn('claude', args, {
    env: {
      ...process.env,
      ...(opts.systemPrompt ? { CLAUDE_SYSTEM_PROMPT: opts.systemPrompt } : {}),
    },
    stdio: ['ignore', 'pipe', 'pipe'],
  });

  let buffer = '';
  for await (const chunk of child.stdout!) {
    buffer += chunk.toString();
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';
    for (const line of lines) {
      if (!line.trim()) continue;
      try {
        const msg = JSON.parse(line);
        if (msg.type === 'assistant' && msg.message?.content) {
          for (const block of msg.message.content) {
            if (block.type === 'text') yield block.text;
          }
        }
        if (msg.type === 'result') return;
      } catch {
        // 非 JSON 行，跳过
      }
    }
  }
}
```

**检查点**：
- [ ] `npx wscat -c ws://localhost:3000` 发消息能看到流式输出
- [ ] ctrl+C 杀后端，子进程也跟着消失（检查 `child.kill()` 是否在清理里）

**这一步最容易踩的坑**：`claude --output-format stream-json` 的确切参数名，
不同版本可能不同。先在命令行手跑一遍，看 NDJSON 长什么样，再写解析器。

### M2 · 身份注入（1 天）

**做完能演示**：配置文件里写 Agent 叫"Alice，擅长后端"，对话里体现出来了。

### M3 · 多 Agent + @ 路由（3~4 天）

**做完能演示**：用户说 `@alice 帮我写个接口`，Alice 回复；  
Alice 回复里写了 `@bob 这个接口需要前端联调`，Bob 自动被叫醒。

```typescript
// src/routing/mention-parser.ts
const MENTION_REGEX = /^@([a-zA-Z0-9_-]+)\s+(.+)/s;

export function parseMention(text: string): { target: string; content: string } | null {
  const m = text.match(MENTION_REGEX);
  if (!m) return null;
  return { target: m[1], content: m[2] };
}

// src/routing/guards.ts
const MAX_DEPTH = 5;  // Clowder 用 15，我们保守一些

export function checkDepth(depth: number): void {
  if (depth >= MAX_DEPTH) throw new Error(`depth_limit_exceeded: ${depth}`);
}

export function checkSelfCall(callerName: string, targetName: string): void {
  if (callerName === targetName) throw new Error(`self_call: ${callerName}`);
}
```

```typescript
// src/routing/route-serial.ts
export async function* routeMessage(
  text: string,
  senderName: string,
  depth: number,
  agents: Record<string, AgentIdentity>,
): AsyncGenerator<{ from: string; text: string }> {
  const mention = parseMention(text);
  if (!mention) {
    // 没有 @ 就是对话结束
    return;
  }

  checkDepth(depth);
  checkSelfCall(senderName, mention.target);

  const targetIdentity = agents[mention.target];
  if (!targetIdentity) {
    yield { from: 'system', text: `Agent ${mention.target} 不存在` };
    return;
  }

  let fullReply = '';
  for await (const chunk of invokeAgent({
    prompt: mention.content,
    systemPrompt: targetIdentity.systemPrompt,
  })) {
    yield { from: mention.target, text: chunk };
    fullReply += chunk;
  }

  // 递归：目标 Agent 的回复里可能还有 @
  yield* routeMessage(fullReply, mention.target, depth + 1, agents);
}
```

**这是整个项目里最有意思的递归**。
Clowder 在 `route-serial.ts` 里用的是完全相同的模式——
`yield*` 递归 + 深度守卫，你可以直接翻原代码对照看。

### M4 · 会话管理 + 抗压缩（3~4 天）

**做完能演示**：对话超过 N 轮 → 提示"已封存，新会话继续" →  
新会话里 Agent 仍然知道自己在做什么。

**核心判断**：封存时往 systemPrompt 开头加什么？

```typescript
// src/agent/session.ts
import Database from 'better-sqlite3';

const db = new Database('sessions.db');
db.exec(`
  CREATE TABLE IF NOT EXISTS sessions (
    id TEXT PRIMARY KEY,
    agent_name TEXT,
    digest TEXT,         -- 封存时的摘要
    message_count INT,
    created_at TEXT,
    sealed_at TEXT
  )
`);

export interface Session {
  id: string;
  agentName: string;
  digest: string;
  messageCount: number;
}

export function sealSession(session: Session): void {
  db.prepare(`
    UPDATE sessions SET sealed_at = ?, digest = ? WHERE id = ?
  `).run(new Date().toISOString(), session.digest, session.id);
}

// 生成摘要（最简版：直接截最后 N 条消息的文本）
export function buildDigest(messages: string[]): string {
  const last = messages.slice(-5).join('\n---\n');
  return `[上下文摘要]\n任务进行中。最近对话：\n${last}\n[摘要结束]`;
}
```

**新会话的 systemPrompt 前缀**：

```typescript
function buildResumePrompt(identity: AgentIdentity, digest: string): string {
  return [
    digest,           // 摘要放最前面，保证新 session 读到
    '',
    identity.systemPrompt,
  ].join('\n');
}
```

**什么时候封存**：超过 token 阈值 or 超过轮次上限。
最简单的检测：`claude --output-format stream-json` 的 `result` 消息里有 `usage` 字段。

**检查点**：
- [ ] 20 轮对话后，手动触发封存，看新 session 里 Agent 能否接着回答"我们上一步做到哪了"
- [ ] 封存的 digest 确实被注入到了新 session 的 systemPrompt 开头

### M5 · 记忆与检索（4~5 天）

**做完能演示**：说"上次我们讨论过 WebSocket 的重连策略" → Agent 能找到并引用。

```typescript
// src/memory/fts.ts
const db = new Database('memory.db');
db.exec(`
  CREATE VIRTUAL TABLE IF NOT EXISTS memories USING fts5(
    content,
    agent_name,
    session_id,
    created_at UNINDEXED
  )
`);

export function addMemory(content: string, agentName: string, sessionId: string): void {
  db.prepare(`INSERT INTO memories VALUES (?, ?, ?, ?)`).run(
    content, agentName, sessionId, new Date().toISOString()
  );
}

export function searchMemory(query: string, limit = 5): Array<{ content: string; agentName: string }> {
  return db.prepare(`
    SELECT content, agent_name AS agentName
    FROM memories
    WHERE memories MATCH ?
    ORDER BY rank
    LIMIT ?
  `).all(query, limit) as any;
}
```

**关键取舍**：先用 FTS5，不上向量检索。
等做完里程碑 6、7 之后，如果你觉得搜不准，再加 `@xenova/transformers` 做本地 embedding。
过早优化会把时间全花在向量检索上，而不是多 Agent 编排。

### M6 · 跨模型互审（2~3 天）

**做完能演示**：Alice（Claude）写完代码 → Bob（Gemini 或另一个 Claude 实例）自动来 review。

```typescript
// src/review/matcher.ts
const REVIEWER_PRIORITY: Record<string, string[]> = {
  'claude': ['gemini', 'codex', 'claude'],  // 优先选不同 provider
  'gemini': ['claude', 'codex', 'gemini'],
  'codex':  ['claude', 'gemini', 'codex'],
};

export function selectReviewer(
  authorProvider: string,
  availableAgents: Array<{ name: string; provider: string }>,
): string | null {
  const priority = REVIEWER_PRIORITY[authorProvider] ?? ['claude'];
  for (const preferredProvider of priority) {
    const candidate = availableAgents.find(
      a => a.provider === preferredProvider
    );
    if (candidate) return candidate.name;
  }
  return null;
}
```

**这一步的核心是"不能自审"**——
`authorProvider !== reviewerProvider` 这个护栏必须在这里加，
后面加就是改接口。

### M7 · 一套纪律（3~4 天）

**做完能演示**：Agent 在"规划阶段"会自动加载一段规划提示；
触发"硬规则"时（比如"不得直接写入生产"），被系统拦下并解释原因。

```typescript
// src/sop/gate.ts
export type Phase = 'planning' | 'coding' | 'review' | 'done';

const PHASE_PROMPTS: Record<Phase, string> = {
  planning: '\n\n[当前阶段：规划] 先列出方案和步骤，不要写代码。',
  coding:   '\n\n[当前阶段：编码] 严格按规划实现，不要改需求。',
  review:   '\n\n[当前阶段：审查] 只指出问题，不要自己改代码。',
  done:     '',
};

export function injectPhasePrompt(systemPrompt: string, phase: Phase): string {
  return systemPrompt + PHASE_PROMPTS[phase];
}

// 简单的 predicate 检查
const HARD_RULES: Array<{ pattern: RegExp; reason: string }> = [
  { pattern: /production|prod|生产环境/, reason: '不得在规划阶段提到生产环境' },
  { pattern: /rm -rf|drop table/i,       reason: '危险操作需要显式确认' },
];

export function checkHardRules(content: string): { blocked: boolean; reason?: string } {
  for (const rule of HARD_RULES) {
    if (rule.pattern.test(content)) {
      return { blocked: true, reason: rule.reason };
    }
  }
  return { blocked: false };
}
```

**这是 Clowder SOP 门禁的 1/10 版本**，但它讲得通——
面试时说"我实现了最简版的 predicate 检查，Clowder 那边有七种 predicate 类型，
我只做了 regex 和 keyword 两种，这已经能演示护栏的概念了"，
这个答法比"我完整实现了全部七种"更可信。

## 5. 关键设计决策速查

做到每个里程碑时，下面这些问题面试官会问，**你必须有一个自己的答案**（不一定和 Clowder 一样）：

| 里程碑 | 面试问题 | 你需要有答案 |
|---|---|---|
| M1 | 为什么用子进程而不是 API？ | 成本 / 认证方式 / 流式输出控制 |
| M2 | 身份注入在哪里？每轮都注入吗？ | systemPrompt vs 每轮前缀的取舍 |
| M3 | 路由深度上限怎么定的？ | 5/10/15 都行，但要说出理由 |
| M3 | 并行路由为什么留到后面做？ | 并发写同一会话会冲突，需要先有锁 |
| M4 | 摘要怎么生成的？ | 截最后 N 条 / 关键词提取 / 调 LLM 总结 |
| M4 | 封存时机怎么判断？ | token count / 轮次 / 手动触发 |
| M5 | 为什么不上向量检索？ | FTS5 够用 + 省依赖 + 可以后加 |
| M6 | 互审结果怎么处理？ | 给用户看 / 自动修改 / 打标记 |
| M7 | predicate 规则怎么管理？ | YAML 配置 / 代码写死 / 数据库 |

## 6. 开工前的三件事

1. **写 `docs/VISION.md`**（300 字，说清楚这是什么、不是什么）  
   不写这个，AI 每次都要重新建立上下文，浪费 30% 的 token。

2. **git init + 第一个 commit**（哪怕只有 README）  
   这样每次 AI 改坏了，`git diff` 一目了然。

3. **先跑通 M1，再开 AI 会话做 M2**  
   不要在 M1 没通的情况下问 AI 怎么做 M3——AI 会写出来，
   但你不知道 M1 的坑在哪里，后面全是叠在沙子上的。
