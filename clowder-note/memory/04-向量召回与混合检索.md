## 本篇从第 3 篇的哪个状态继续？

第 3 篇已经产生一份词法候选。现在猫想问“同一条请求又发一次，为什么出现两条消息”，文档可能写的是“请求重放与幂等副作用”，字面并不一致。向量提供另一种发现线索。

我们追三条相连的线：

```text
写入：文本 → 向量 → 与 anchor 绑定保存
查询：问题 → 向量 → NN 候选 → 回表过滤 → RRF
消费：EvidenceItem → API JSON → MCP 文本 → 原文下钻
```

本篇最重要的区分是：**相似向量不是完整文档，向量距离不是最终排序分，搜索工具返回也不等于已经读完原文。**

## 1. 先看输入：到底对什么文字做 embedding？

文档/thread 级：

```ts
const texts = batch.map((i) => `${i.title} ${i.summary ?? ''}`);
const vectors = await ctx.embedding.embed(texts);
```

Passage 级则直接用 `p.content`。

例如同一 thread 可能有：

```text
文档级输入：回调重复消息排查 [user] 为什么重复...[cat] 可能响应丢失...
片段级输入：决定使用稳定业务键，避免重试再次产生副作用。
```

它们代表不同粒度。文档级是导航卡片，片段级保留更具体的消息内容。普通 Markdown 的文档 summary 主要是短摘录，不是全文压缩到一个神奇向量。没进入待编码文本的信息，不会被模型凭空编码进去。

依据：[embedIndexedItems / embedPassages](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/embed-utils.ts#L17)。

## 3. TypeScript 客户端做了哪几次数据变形？

`EmbeddingService.embed()` 先按批次调用 embedBatch。HTTP body 是：

```json
{"input":["第一条待编码文字","第二条待编码文字"]}
```

不是把 EvidenceItem 整个对象发给模型。endpoint 由服务配置解析，调用 `/v1/embeddings`，带 `AbortSignal.timeout(timeoutMs)`。默认超时 3000ms、客户端目标维度 768；它们是配置，不是性能测量。

响应中的 data 先按 `index` 排序，再拷贝进 Float32Array。为什么要排序？因为后续使用 `vectors[i]` 配回 `batch[i].anchor`。如果服务返回顺序变化而不恢复 index，A 文档可能拿到 B 的向量，数据库结构却看起来完全合法。

这说明“向量表有 N 行”不是完整性验证，映射关系同样重要。

依据：[embed 与 embedBatch](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/EmbeddingService.ts#L112)。

## 4. Python 服务怎样截断并归一化？

项目自带服务的相关后端都有“截到目标维度，再做 L2 归一化”的路径：

```python
truncated = raw[:, :embed_dim]
norms = np.linalg.norm(truncated, axis=1, keepdims=True)
norms = np.where(norms > 0, norms, 1.0)
return truncated / norms
```

带入一个只为算清楚的例子：原向量 `[3,4,0,7,9]`，目标维度 3。

1. 截断：`[3,4,0]`。
2. 范数：`sqrt(3²+4²)=5`。
3. 除以范数：`[0.6,0.8,0]`。

先截断再归一化，才能让留下的那部分具有单位长度。若先把五维归一化再直接截到三维，留下的三维长度通常不再是 1。

零向量的范数会替换为 1 来避免除零，但零向量仍是零向量，不能把它当普通单位向量讨论余弦。

另外，TypeScript 客户端也会按它自己的 targetDim 复制：太长就截断、太短剩余补零。若外部服务和客户端维度配置不一致，客户端进一步截断后没有在这段代码里重新归一化。因此“自带后端有 normalize”不意味着任何配置下最终入库向量都满足同一前提。

依据：[Python MLX 路径](D:/AI/clower-1/clowder-ai/scripts/services/embed-api.py#L218)、[fastembed 与 fallback](D:/AI/clower-1/clowder-ai/scripts/services/embed-api.py#L230)、[客户端维度复制](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/EmbeddingService.ts#L141)。

## 5. 三组批量数字为什么不能混为一个？

| 工作 | 数量 |
|---|---:|
| 缺失 passage 向量的数据库扫描 | 每批 256 |
| Passage embedding 助手发送 | 每批 8 |
| 通用 EmbeddingService 的分批上限 | 64 |

数据库一次拿 256 行，不代表一次发送 256 段给模型。先筛出缺向量的 K 行，再分成 8 条一批。通用服务收到 8 条，无需等到 64 才执行。

真正昂贵的模型计算量与缺失文本量相关，但数据库为了发现“缺哪些”仍有扫描成本。第 1 篇已展开旧向量失效和缺失补齐，这里不要把它误写成每次全库重新 embedding。

依据：[扫描批次](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/IndexBuilder.ts#L953)、[embedding 助手](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/embed-utils.ts#L5)。

## 6. 向量存储：同一条资料的正文和向量靠什么关联？

文档表：

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS evidence_vectors USING vec0(
  anchor TEXT PRIMARY KEY,
  embedding float[目标维度]
)
```

Passage 表的键则是：

```ts
JSON.stringify([docAnchor, passageId])
```

例如 `["thread-T42","msg-m101"]`。读取时解析并验证是两个字符串的数组。它比随意拿一个冒号拼接更容易避免分隔符歧义。

本任务直接执行了 key 编解码函数：带有冒号、斜杠、方括号的两段内容仍可正确往返；`[1,"x"]` 被拒绝。验证的是 key 协议，不是向量相似度。

VectorStore 的 upsert 是 DELETE 再 INSERT。这里的“upsert”是方法语义，不是底层一定使用一条带 ON CONFLICT 的 SQL，也不能自动推论两条未单独包裹的语句是原子替换。

依据：[向量表](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/schema.ts#L755)、[VectorStore CRUD](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/VectorStore.ts#L8)、[Passage key](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/PassageVectorStore.ts#L5)。

## 7. 距离、KNN、HNSW 是三种不同概念

当前源码使用 vec0 的 `MATCH ? AND k=?`，未显式覆盖 distance_metric；锁文件版本为 sqlite-vec 0.1.9。核对该版本上游源码，浮点向量列的默认度量是 L2。没有 HNSW 配置不能说这里采用了 HNSW。

```text
L2：怎样计算两个向量的差异
KNN：选择距离最近的 K 个
HNSW：一种实现近似近邻搜索的索引方法
RRF：把多份候选名次融合
```

上游版本参考（不是本轮加载 vec0 跑了 KNN）：

### 7.1 用小向量把距离算出来

数学例子，不代表真实 embedding：

```text
q = [1,0,0]
A = [0.8,0.6,0]
B = [0,1,0]
C = [1,0,0]
```

L2 距离：C=0；A=sqrt(0.2²+0.6²)=sqrt(0.4)≈0.6325；B=sqrt(2)≈1.4142。K=2 会取 C、A。

如果两个非零向量都已单位归一化：

```text
||q-x||² = ||q||² + ||x||² - 2 q·x = 2 - 2 cos(q,x)
```

所以在这个前提下，L2 由小到大的排序与余弦由大到小等价。不能直接用 `1-distance` 充当余弦；应该是 `1-distance²/2`。配置截断破坏单位长度时，也不能继续套该等价关系。

这些只是向量层排序性质，后续 RRF、authority、消费重排都可能改变最终顺序。

## 8. 换模型后为什么必须考虑旧向量？

想象旧模型把“幂等”编码到坐标系 A，新模型把同一概念编码到坐标系 B。即使都是 768 维，两套位置也不保证可直接比较。

VectorStore 保存 modelId、modelRev、dim，但当前 checkMetaConsistency 实际比较 modelId 与 dim，不比较 modelRev。

本任务用原始 VectorStore 的元数据方法验证：

| 旧元数据 | 新元数据 | 实际检查 |
|---|---|---|
| model-a/r1/3维 | model-a/r2/3维 | consistent=true |
| model-a/r1/3维 | model-b/r1/3维 | consistent=false |

因此不能声称 revision-only 更新必然触发重建。

批量助手还有入口条件：`items.length===0` 会先返回；只有继续执行、服务 ready、存在 allDocsProvider 并检测不一致，才清向量、取全部文档重编码。看见“有重建代码”不代表任何模型更新场景都无条件到达它。

依据：[模型元数据](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/VectorStore.ts#L32)、[重建顺序](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/embed-utils.ts#L17)。

## 9. 查询时，向量层先返回一张轻量名单

真实 SQL：

```sql
SELECT anchor, distance FROM evidence_vectors
WHERE embedding MATCH ? AND k = ?
```

输入 queryVec 与 K，输出不是整篇文章，而是：

```text
anchor=A, distance=...
anchor=B, distance=...
```

只有这张名单，API 还不知道 title、kind、status、sourcePath 等完整内容，也不能完成 thread、world 等业务筛选。

因此下一步叫 hydration：按 anchor 回 evidence_docs，把轻量命中还原成完整 EvidenceItem。把它理解成“拿到书号后，再去目录取书的完整资料”。

## 10. 为什么后置过滤会造成“库里明明有，却没返回”？

文档 NN 函数先拿到有限全局候选，然后按 anchor IN 查询主表并追加过滤。Passage 也会解析复合 key，再按 doc_anchor、日期等限制回表。

假设希望只查 T42，向量层全局榜单前 20 条全属于其他 thread，而 T42 最好的资料在全局第 21：

```text
先 Top20 → 只剩其他 thread → 按 T42 过滤 → 空
```

如果算法是先限定 T42 再计算它内部 Top-K，会得到不同结果。两个操作不可交换。

源码通过候选池放大缓解这个问题，但只要池仍有限，就不能保证等价于真正的过滤内 Top-K。这个缺口是召回充分性问题；“输出不得越界”则是另一项正确性问题，两者必须分开测试。

依据：[文档 NN 回填条件](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L1263)、[passage 回表](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L830)。

## 11. 开始融合：先把原始距离放到一边

第 3 篇带来词法榜；本篇带来向量榜。两边原始分数不是同一尺度，RRF 不把 BM25 与 L2 距离直接相加，而是只使用名次。

这里另用一组固定榜单演示，区别于前面的三维数学例子：

```text
词法榜：A, x1, x2, x3, B
向量榜：B, v0, v1, ... v7, A
```

A 词法下标0、向量下标9；B 词法下标4、向量下标0。

真实累加循环：

```ts
for (let i = 0; i < lexicalResults.length; i++) {
  const anchor = lexicalResults[i].anchor;
  scores.set(anchor, (scores.get(anchor) ?? 0) + 1 / (RRF_K + i));
}
for (let i = 0; i < nnResults.length; i++) {
  const anchor = nnResults[i].anchor;
  scores.set(anchor, (scores.get(anchor) ?? 0) + nnWeight / (RRF_K + i));
}
```

这里 i 从 0 开始，RRF_K=60。没有出现在一侧，就没有那一侧贡献，不是给它虚构一个最后名次。

依据：[hybridRRFSearch](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L1230)。

## 12. RRF 的中间 Map 怎么变化？

先处理词法榜：

```text
scores[A] = 1/60
scores[B] = 1/64
```

再处理向量榜：

```text
scores[B] += w/60
scores[A] += w/69
```

本轮从源码提取并执行的就是这两个累加循环，固定 NN 名单不是模型输出。结果：

| 向量权重 w | A | B |
|---|---:|---:|
| 1 | 0.0311594203 | 0.0322916667 |
| 1.5 | 0.0384057971 | 0.0406250000 |

两种情况下 B 都在 A 前。包含 CJK 字符时，当前代码使用 w=1.5；这是一条确定性规则，不是请求时现场学习出来的语言权重。

这里也能说明 RRF 的限制：它忽略原始榜内分数间距。“第一名领先第二名很多”与“只领先一点”在名次贡献上没区别。这是用尺度稳定性换掉了一部分分数强度信息。

## 13. 候选池如何一步步放大？

普通最终 limit=5：词法 hybrid 池按 `min(max(5×4,20),100)` 得到20。进入文档 RRF 的内部 limit 若因消费重排打开而放大为15，NN 池还可能相应成为60。

要追清每个变量属于哪个阶段：最终 limit、词法池、供重排的中间数量、NN 搜索池不能只叫一个 K。

候选池过小会漏掉“两边都还不错但单边没进前5”的资料；过大会增加距离查询、回表和后处理成本。源码的20/100并不是经本轮证明的最优值，调参应使用固定金标查询集。

依据：[hybrid 中间池](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L499)、[内部 NN 池](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L1237)。

## 14. Raw passage 融合还维护“来自哪条召回”的标记

Raw 不只是把 summary 结果加一段内容。它有独立 passage 词法、NN 和 RRF，随后按 docAnchor 归组。

词法和 NN 的同一片段用 JSON pair key 去重。若某片段先在词法榜出现，又在 NN 榜出现，程序会让向量对象带 `_alsoLexical=true`；纯 NN 对象则没有这项双路命中标记。

```text
仅词法：不是纯语义新发现
仅 NN：semanticHit=true，alsoLexical 不为 true
两路都有：semanticHit=true，alsoLexical=true
```

这些标记不是为了显示一个漂亮徽章，而是参与后面的父条目接纳条件。

依据：[hybridPassageRRFSearch](D:/AI/clower-1/clowder-ai/packages/api/src/domains/memory/SqliteEvidenceStore.ts#L790)。

## 16. API JSON 到模型文本，又被裁了一次

API 将 summary 映射为 snippet，按最终返回下标映射 confidence，kind 映射成 sourceType。thread/session 在该映射中属于 discussion，不能把两个枚举直接等同。

MCP handler 则整理为文本：

```text
[high] 某个标题
  anchor: thread-T42
  sourcePath: ...
  snippet: ...
  passages: ...
  下一步读取工具与坐标
```

实际截断：snippet 最多前200字符；每个 passage 前150字符；相邻片段前120字符。最后包装为 `content:[{type:'text',text}]` 返回宿主。

因此“请求 depth=raw”与“模型看完原文”仍然不同。原始数据库里有完整片段，但这次工具返回可能只是短摘录；完整理解依赖后续下钻。

依据：[API 映射](D:/AI/clower-1/clowder-ai/packages/api/src/routes/evidence.ts#L257)、[MCP 格式化和截断](D:/AI/clower-1/clowder-ai/packages/mcp-server/src/tools/evidence-tools.ts#L287)、[ToolResult](D:/AI/clower-1/clowder-ai/packages/mcp-server/src/tools/file-tools.ts#L34)。

## 17. 服务失败时，为什么两条路径报告不一样？

Summary 路径中，embedding 不可用或向量搜索异常，会退到词法候选；其中一些返回仍是 `degraded:false`。

Raw passage 路径则会明确写：


## 18. 复杂度、不变量与应对追问

RRF 两榜各 K 个时，累加约 O(K)，合并排序约 O(K log K)；但完整请求还包含 embedding 网络时间、NN、回表、过滤、父对象组装和输出格式化。不能把 RRF 复杂度当整条搜索复杂度。

应维持的不变量包括：输入第 i 条对应第 i 个向量；key 能定位唯一对象；回表结果仍满足业务范围；正文改变后旧向量不可当作新正文表示；距离分数与业务置信分不同。当前实现的门控、后置过滤和元数据比较并不让所有不变量自动无条件成立。

**问：为什么不是只用向量？**  
答：编号/名字精确性、实体范围和版本关系不是语义相似度能包办；项目保留关键词与结构化路径。

**问：RRF 是加 BM25 和 L2 分数吗？**  
答：不是，按两张榜的名次加倒数贡献。我们已经用原始循环跑出 A/B 的中间分数。

**问：为何过滤后为空？**  
答：可能先取全局有限 NN 池，再过滤把它清空；这不等于目标范围里没有任何相关向量。

**问：为何相同维度还要重建？**  
答：模型坐标系可能变了；当前检查 modelId/dim，但 revision-only 实际不触发不一致。

**问：原文存在，为什么 Agent 还误解？**  
答：待编码粒度、候选排名、MCP 截断和是否下钻都可能造成信息缺口，要沿链查，不只调距离。

**问：本轮验证了什么？**  
答：原始 RRF 累加片段、key 编解码和模型元数据检查；NN 名单是固定 fixture，未跑真实 embedding/vec0，不把数学例子当生产性能。
